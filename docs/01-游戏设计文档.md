# 米拉奇战纪 · 游戏设计文档 (GDD v3.0)

> 数值表由 `data/*.json` **自动生成**，与代码永远一致。引擎 Godot 4.6.1 (.NET)，逻辑层纯 C#。

---

## 1. 概述

双人实时对抗 + 回合经营 + 自动战斗。双方城邦各 190 点生命。

```
战后对敌方城邦造成的伤害 = max(0, 我方存活单位杀戮值总和 − 敌方存活单位杀戮值总和)
```

回合结构：**备战（35 秒）→ 交战（最长 30 秒）→ 结算（按杀戮值差扣城邦血，然后清空战场）**

---

## 2. 核心循环与部队规则

```
① 备战阶段
   · 经济结算（基础 5 金 + 利息 + 连胜连败奖励 + 遗物产出）
   · 兵种商店 = 全部【等级已解锁】的兵种，翻页浏览，任选
   · 点击卡片购买（一次一只）→ 进入【待出战队列】
   · 在队列里选中一个 → 点战场自己那半边放下；点已上场的可撤回
   · 每 2 回合：肉鸽遗物三选一；宝石商店（下回合生效）
② 交战阶段：点技能 → 点战场释放
③ 结算阶段：扣城邦生命 → 清空战场 → 下回合按阵容满血重新摆出
```

**部队是永久名册**：买下的兵永久属于你，战斗中阵亡不会失去它。
「存活」只决定当回合对城邦的伤害。

---

## 3. 经济、等级与解锁

| 项 | 规则 |
|---|---|
| 基础收入 | 5 金 / 回合 |
| 利息 | 每 10 金产 1 金，上限 5 |
| 连胜连败 | 2 连 +1，3 连 +1，4 连 +2，5 连及以上 +3 |
| 等级 | 起始 3，最高 12；买经验 4 金 = 4 点 |
| 人口上限 | **= 等级 + 1** |
| **兵种解锁** | **按等级解锁**（Lv1 / Lv3 / Lv5 / Lv7 / Lv9 / Lv11），等级不够不会出现在商店 |

升级所需经验：0 / 2 / 2 / 6 / 10 / 16 / 26 / 40 / 58 / 78 / 100 / 130

---

## 4. 战斗规则

```
物理伤害 = max(物攻 × (1 − 物防/(物防+75)), 物攻 × 0.2)
魔法伤害 = max(魔攻 × (1 − 魔防/(魔防+75)), 魔攻 × 0.2)
```

伤害下限保证低攻单位不会被高防单位完全免疫。

## 9. 美术与界面

- 每个兵种有**程序化生成的 3D 模型**（11 种骨架：人形/重甲/法师/兽形/机械/巨人/飞行/巨龙/元素/树人/蛛魔/恶魔）
- 启动时离屏烘焙成 256×256 立绘，商店卡片、悬浮属性卡、战场单位统一使用
- 界面为中世纪魔法城邦风格：羊皮纸面板 + 錾金边框 + 铆钉装饰 + 符文法阵战场
- 资源与属性全部用**图标 + 数字**表示；商店卡片可翻页、悬浮看属性、点 ⓘ 打开可旋转 3D 详情
- 替换正式美术只需替换 `art/units/` 下的同名文件或改 `UnitModel.Build()`，详见 `art/README.md`

```powershell
dotnet run -- matrix 18     # 7 大流派两两对战胜率矩阵
dotnet run -- ladder 60     # AI 难度阶梯
dotnet run -- battle 600    # 纯战斗公平性（同阵容镜像对战，检验模拟是否对称）
dotnet run -- diag greed undead_swarm   # 单局逐回合诊断
```

### 已修复的对称性缺陷（排查记录）

| 现象 | 根因 | 修复 |
|---|---|---|
| 纯战斗左右偏差 18% | 单位处理顺序固定，左方永远先手 | 每 tick 用种子随机数打乱处理顺序 |
| 近战阵容仍有 9% 偏差 | `Separate()` 边遍历边改坐标，累加结果与列表顺序相关 | 改为先累加推力再统一应用 |
| 所有对局完全相同 | 战斗随机数是写死的常量 | 用对局种子初始化 |
| 部署位置左右不同 | 双方各自抽随机数，先抽的一方不同 | 改为严格镜像的确定性阵型 |
| 整体左右偏差 12~27% | 双方共用随机数流、固定由 0 号先结算商店/遗物 | 每回合交替结算顺序 |

当前实测：纯战斗偏差 1.3%~2.7%（噪声范围），300 局对局偏差 ~3-9%。
